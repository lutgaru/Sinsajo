## Why Sinsajo?

<CardGrid stagger>
  <Card title="Real-time" icon="rocket">
    ~150–300ms end-to-end latency. See text as you speak, with Voice Activity Detection (Silero VAD v5) sending only speech segments.
  </Card>
  <Card title="100% Private" icon="approve-check-circle">
    Self-hosted Rust server. No API keys, no cloud. Your audio never leaves your network. Optional local WAV/OGG recording.
  </Card>
  <Card title="Multi-platform" icon="laptop">
    Flutter client for Android, iOS, Desktop and **Web**. Rust server runs anywhere — Docker, bare metal, VPS.
  </Card>
  <Card title="Multi language" icon="translate">
    Multi-language target selection (en/es/fr/de/pt). English via Parakeet, translation via Canary.
  </Card>
</CardGrid>

## How it works

```
┌─────────────────┐         WebSocket          ┌──────────────────┐
│  Flutter Client │ ◄─────────────────────────►│   Rust Server    │
│  (Dart/Silero)  │    PCM 16-bit / JSON       │ (transcribe-rs)  │
└─────────────────┘                            └──────────────────┘
       │                                                 │
       │ Silero VAD v5                                   │ ONNX Model
       │ (ONNX Runtime)                                  │
       ▼                                                 ▼
 ┌─────────────────┐                             ┌──────────────────┐
 │  AudioService   │                             │  Canary 180M     │
 │  + vad package  │                             │  Flash /         │
 │  (ML-based)     │                             │  Parakeet TDT    │
 └─────────────────┘                             └──────────────────┘
```

<Steps>

1. **Capture** — Flutter records PCM 16-bit @ 16kHz
2. **Detect** — Silero VAD v5 detects speech (ONNX Runtime)
3. **Transmit** — Only speech chunks sent over WebSocket
4. **Transcribe** — Rust server runs Canary 180M Flash or Parakeet TDT 0.6B (Int8)
5. **Display** — Real-time text + optional server-side WAV/OGG recording

</Steps>

## Sinsajo needs two parts to work

<Aside type="caution" title="Client + Server required">
  Sinsajo is **not** standalone. You always need a **Server** (Rust — runs the AI model) and a **Client** (Flutter — captures audio and shows text). They talk over WebSocket `ws://YOUR_SERVER_IP:8765`. Run one server, connect any clients to it.
</Aside>

### 1. Start a Server — pick one

<Tabs>
  <TabItem label="Docker Compose (recommended)">
    Best for a Linux server or homelab. Models and recordings are persisted in volumes.

    ```yaml
    # docker-compose.yml
    services:
      sinsajo-server:
        image: lutgaru/sinsajo-server:latest
        ports: ["8765:8765"]
        volumes:
          - sinsajo_models:/app/models
          - sinsajo_records:/app/records
        restart: unless-stopped
    volumes:
      sinsajo_models:
      sinsajo_records:
    ```
    ```bash
    docker compose up -d
    # -> ws://localhost:8765 (auto-downloads ~2-3GB model on first run)
    ```
  </TabItem>
  <TabItem label="Docker CLI">
    Same image, single command — no compose file needed.

    ```bash
    docker pull lutgaru/sinsajo-server:latest
    docker run -p 8765:8765 \
      -v sinsajo_models:/app/models \
      -v sinsajo_records:/app/records \
      lutgaru/sinsajo-server:latest
    ```
  </TabItem>
  <TabItem label="Precompiled binary">
    No Docker needed. Download the binary for your platform and run it.

    ```bash
    # GitHub Releases -> server/v* assets
    # - sinsajo-server          (linux x86_64)
    # - sinsajo-server.exe      (windows x86_64)
    ./sinsajo-server --model ParakeetTDT --autodownload-model --port 8765
    # or on Windows: .\sinsajo-server.exe --model ParakeetTDT --autodownload-model
    ```
    Grab it from [server-latest](https://github.com/lutgaru/Sinsajo/releases/tag/server-latest) — no compile, just run.
  </TabItem>
  <TabItem label="Build from source">
    For any architecture that meets the minimum requirements (Rust 1.70+, ~500MB RAM per Int8 model).

    ```bash
    git clone https://github.com/lutgaru/Sinsajo.git
    cd Sinsajo/server
    cargo run --release -- --model ParakeetTDT --autodownload-model
    # or: cargo build --release && ./target/release/sinsajo-server --help
    ```
    See [Server Guide](/Sinsajo/guides/server/) for CLI flags and GPU acceleration.
  </TabItem>
</Tabs>

### 2. Connect a Client — pick one

<Tabs>
  <TabItem label="Web App (no install)">
    Fastest way to try it — nothing to install.

    1. Make sure your **server** is running and reachable (`ws://YOUR_SERVER_IP:8765`)
    2. Open the **Web App** → [Try Web App](/Sinsajo/app/)
    3. In **Settings** set the server IP, tap the mic and speak

    Requires HTTPS for microphone access (GitHub Pages provides it).
  </TabItem>
  <TabItem label="Android APK">
    For Android phones/tablets. Share via link or QR.

    - Download `app-release.apk` from [client-latest](https://github.com/lutgaru/Sinsajo/releases/tag/client-latest)
    - Enable *Install unknown apps* → install → set server IP in Settings → speak

    APKs are built on every `client/v*` tag via GitHub Actions — not stored in git.
  </TabItem>
  <TabItem label="Build Flutter app">
    For any platform that meets client requirements (Flutter 3.x). Compile for Android, iOS, Linux, macOS, Windows or Web.

    ```bash
    git clone https://github.com/lutgaru/Sinsajo.git
    cd Sinsajo/sinsajo_client
    flutter pub get
    # optional: edit lib/providers/transcription_provider.dart -> kWsUrl
    flutter run          # run on connected device
    flutter build apk    # Android
    flutter build web --base-href /Sinsajo/app/
    ```
    See [Client Guide](/Sinsajo/guides/client/).
  </TabItem>
</Tabs>

<Aside title="Try it in 60 seconds">
  1. `docker compose up -d` → server on `ws://localhost:8765`
  2. Open [Web App](/Sinsajo/app/) → Settings → set `localhost` or your LAN IP → tap mic.
</Aside>

## At a glance

| Metric | Value |
|--------|-------|
| Latency | ~150–300ms chunk → text |
| CPU | ~20–40% (1 core) |
| RAM | ~500MB (Int8 quantized) |
| Accuracy | ~95% clean Spanish |
| Bandwidth | ~256KB/s (PCM, VAD reduces ~60%) |

<Aside title="APK Distribution">
  APKs are **not** stored in `git`. Every tagged release `client/v*` builds the APK via GitHub Actions and attaches it to the GitHub Release. Link directly to `https://github.com/lutgaru/Sinsajo/releases/tag/client-latest/download/app-release.apk` from your landing buttons or share a QR.
</Aside>

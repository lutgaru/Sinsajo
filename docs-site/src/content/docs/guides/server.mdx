<Aside type="tip" title="Runs alone, used by the client">
  The server does transcription and exposes `ws://0.0.0.0:8765` (configurable). It is useless without a **Client** — connect via [Web App](/Sinsajo/app/), APK or a Flutter build. See [Client Guide](/Sinsajo/guides/client/) and [Quick Start](/Sinsajo/guides/quickstart/).
</Aside>

## Options — pick one

<Tabs>
  <TabItem label="Docker Compose (recommended)">
    Best for a Linux server, homelab or VPS. Image `lutgaru/sinsajo-server` from Docker Hub, models/records persisted.

    ```yaml
    # docker-compose.yml
    services:
      sinsajo-server:
        image: lutgaru/sinsajo-server:latest
        ports: ["8765:8765"]
        volumes:
          - sinsajo_models:/app/models
          - sinsajo_records:/app/records
        restart: unless-stopped
    volumes:
      sinsajo_models:
      sinsajo_records:
    ```

    ```bash
    docker compose up -d
    ```

    Or pin a tag: `lutgaru/sinsajo-server:latest` or `server/v*` tag. Pass args after image: `... lutgaru/sinsajo-server:latest --model Canary180M --autodownload-model`.
  </TabItem>
  <TabItem label="Docker CLI">
    Same image, single command without compose file:

    ```bash
    docker pull lutgaru/sinsajo-server:latest
    docker run -p 8765:8765 \
      -v sinsajo_models:/app/models \
      -v sinsajo_records:/app/records \
      lutgaru/sinsajo-server:latest --model ParakeetTDT --autodownload-model
    ```
  </TabItem>
  <TabItem label="Precompiled binary">
    No Docker, no Rust needed — download and run.

    ```bash
    # From GitHub Releases -> server/v* assets:
    # - sinsajo-server        (linux x86_64)
    # - sinsajo-server.exe    (windows x86_64)
    ./sinsajo-server --model ParakeetTDT --autodownload-model --port 8765
    # Windows PowerShell: .\sinsajo-server.exe --model ParakeetTDT --autodownload-model
    # Custom dirs: --model-dir ./models --records-dir ./records
    ```

    Get it at [server-latest](https://github.com/lutgaru/Sinsajo/releases/tag/server-latest). No compilation for `x86_64` Windows/Linux.

    CLI args:

    | Arg | Default | Description |
    |-----|---------|-------------|
    | `--model` | prompt | Model flag (see Models below; e.g. `ParakeetTDT`, `Canary180M`, `Canary1BV2`, `WhisperSmall`) |
    | `--autodownload-model` | `false` | Auto-download if missing |
    | `--port` | `8765` | WebSocket port |
    | `--model-dir` | `./models` | Model storage |
    | `--records-dir` | `./records` | WAV/OGG output |
  </TabItem>
  <TabItem label="Build from source">
    For **any architecture** meeting minimum requirements (Rust 1.70+, ~500MB RAM for Int8, ~2–3GB disk for model).

    ```bash
    git clone https://github.com/lutgaru/Sinsajo.git
    cd Sinsajo/server
    cargo run --release -- --model ParakeetTDT --autodownload-model
    # or
    cargo build --release && ./target/release/sinsajo-server --help
    ```

    Add new models as a module under `server/src/model/` implementing the `Model` trait plus a `ModelDefinition` entry. If `--model` is omitted it reads `sinsajo-config.json`, then prompts.

    Available: see [Supported Models](/Sinsajo/reference/models/) for the full list. The default build is ONNX-only; Whisper needs `--features whisper-cpp` and Whisperfile needs `--features whisperfile`:

    ```bash
    cargo run --release --features whisper-cpp -- --model WhisperSmall --autodownload-model
    cargo run --release --features whisperfile -- --model WhisperfileSmall --autodownload-model
    ```

    An unknown `--model` name prints the flags compiled into your binary plus rebuild hints for feature-gated models.
  </TabItem>
</Tabs>

## Models

The server ships the full local `transcribe-rs` registry — Parakeet, Canary (180M/1B Flash/1B v2), Cohere (int4/int8), SenseVoice, GigaAM, Moonshine (+ streaming), Whisper and Whisperfile. The OpenAI remote engine is intentionally excluded: Sinsajo is 100% offline.

See **[Supported Models](/Sinsajo/reference/models/)** for flags, languages, download sources, manual-install models and feature gates.

Auto-download handles first-run downloads (HuggingFace single files, or mirror tarballs for Moonshine/SenseVoice/Whisperfile). Subsequent starts ~2–3s. Override dirs with `--model-dir` / `--records-dir`. A `.sinsajo_manifest.json` per model tracks installed files so partial downloads are detected.

### Feature-gated builds

Whisper and Whisperfile are compiled out of the default binary to keep it lightweight:

```bash
# Build with one backend
cargo build --release --features whisper-cpp

# Both backends
cargo build --release --features "whisper-cpp whisperfile"

# Docker
docker build --build-arg FEATURES=whisper-cpp -t sinsajo-server:whisper .
```

The published Docker image and precompiled binaries are ONNX-only. `WhisperfileSmall` also starts a local HTTP server on port `8080` (`WHISPERFILE_PORT` overrides it).

## Runtime model manager

Clients can switch models without restarting the server. The **Settings → Server → Model manager** section lists every compiled model, marks installed/active entries, and supports:

- **Download** — fetch a missing model with per-file and aggregate progress
- **Load / Reload** — swap the active model in memory
- **Delete** — remove an installed model (the active model cannot be deleted)

Only one model operation runs at a time. Loading a model broadcasts the new `model_info` and saves the choice to `sinsajo-config.json`. The raw messages are documented in [Protocol → Model manager](/Sinsajo/guides/protocol/#model-manager).

## GPU acceleration

```rust
use transcribe_rs::{set_ort_accelerator, OrtAccelerator};
set_ort_accelerator(OrtAccelerator::Cuda); // or Auto
```

## Translation

Canary supports `target_language` from client `start` message (Flash: en/de/es/fr; v2: 25 languages). Server forwards to `transcribe_with`:

```rust
model.transcribe_with(&samples, &CanaryParams {
  language: Some("es".to_string()),
  target_language: Some("en".to_string()),
  ..Default::default()
})?;
```

Parakeet is English-only and ignores the target language; Whisper/Whisperfile use it as the language hint. See [Protocol](/Sinsajo/guides/protocol/).

## Persistence

- Models: `models/` (or `--model-dir`), one subdirectory per model
- Recordings: `records/` (WAV/OGG, triggered by client `clean`)
- Config: `sinsajo-config.json` (last chosen or loaded model)

## Deployment

The server is **not** deployed to GitHub Pages (static). Run it on your LAN, VPS, fly.io / Railway, etc. with Docker or a binary. Expose `8765` and point clients to `ws://YOUR_IP:8765` or `wss://` behind a reverse proxy (Caddy/Nginx). For remote access consider Tailscale/WireGuard.
